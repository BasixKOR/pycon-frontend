# 세션 목록 다중 연사 사진 표시 설계

## 목적

홈페이지 세션 목록에서 세션 대표 이미지가 없는 경우, 모든 연사를 API 순서대로 보여주고 사진이 없는 연사는 기존 기본 원으로 표시한다.

## 현재 동작

세션 목록은 세션 대표 이미지를 우선 사용한다. 대표 이미지가 없으면 사진이 있는 첫 번째 연사의 사진 한 장만 표시한다. 사용할 이미지가 없거나 이미지 로딩에 실패하면 행사 로고를 표시하며, 행사 로고도 없으면 빈 원형 영역을 표시한다. 연사 이름은 API가 반환한 순서를 그대로 사용한다.

## 확정 동작

1. 세션 대표 이미지가 있으면 현재처럼 대표 이미지 한 장만 표시하고 연사 이름 순서는 변경하지 않는다.
2. 세션 대표 이미지가 없으면 연사와 이름 칩을 API가 반환한 순서 그대로 표시한다.
3. 각 연사는 이미지 격자에서 한 칸씩 차지한다.
   - 사진이 있으면 해당 연사의 사진을 표시한다.
   - 사진이 `null`이면 기존 기본 원을 표시한다. 기본 원에는 행사 로고가 있으면 행사 로고를 넣고, 행사 로고도 없으면 테두리만 있는 빈 원을 표시한다.
4. 연사 사진은 고정 폭의 2열 격자로 표시한다. 연사가 많아지면 행과 세션 카드 높이가 늘어난다.
5. 연사 이름 칩도 API 순서를 유지하므로 이미지 격자의 순서와 일치한다.
6. 연사가 없고 세션 대표 이미지도 없으면 기존 행사 로고 대체 동작을 유지한다.
7. 등록된 이미지 URL의 로딩에 실패하면 해당 연사 칸을 기존 기본 원으로 대체한다.

예시: `A(사진 있음), B(사진 없음), C(사진 있음)`은 이미지 격자 `A 사진, B 기본 원, C 사진`, 이름 `A, B, C` 순서로 표시한다.

## 구현 범위

변경 대상은 공용 `SessionList`의 세션 카드 이미지와 연사 이름 렌더링이다. API 스키마, 세션 상세 페이지, 시간표, 관리자 및 참가자 포털은 변경하지 않는다.

세션 카드 내부에서 세션 대표 이미지가 있는지에 따라 표시할 이미지 목록만 파생한다. 별도의 정렬, 공용 유틸리티 또는 외부 의존성은 추가하지 않는다.

## 반응형 동작

사진 격자의 열 수는 화면 크기와 관계없이 2열을 유지한다. 기존 카드의 텍스트 영역이 지나치게 좁아지지 않도록 이미지 영역의 폭을 고정하고, 추가 사진은 아래 행으로 배치한다. 이미지 수에 따라 카드 높이가 늘어나는 것은 허용한다.

## 검증

다음 경우를 확인한다.

- 세션 대표 이미지가 있는 다중 연사 세션
- 대표 이미지 없이 모든 연사가 사진을 가진 세션
- 대표 이미지 없이 일부 연사 사진이 `null`인 세션
- 대표 이미지 없이 모든 연사 사진이 `null`인 세션
- 대표 이미지와 연사가 모두 없는 세션
- 연사 사진 URL이 로딩에 실패하는 세션
- 데스크톱과 모바일에서 사진 격자 및 텍스트 영역 배치

저장소에 해당 컴포넌트 테스트가 없으므로 기존 타입 검사와 관련 앱 빌드를 실행하고, 대표 사례를 브라우저에서 확인한다.

## 제외 범위

- 사진과 이름 칩 사이의 클릭 연동
- 새로운 연사별 이미지 대체 자산 추가
- 표시할 연사 수 제한 또는 `+N` 축약
- 세션 상세 페이지와 시간표의 연사 표시 변경
